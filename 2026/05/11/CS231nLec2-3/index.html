1. Introduction: The Image Classification Problem

1.1 What is Image Classification

Image Classification is the task of assigning a single label from a fixed set of categories to an input image. It is one of the core problems in computer vision and provides the basis for many other tasks such as object detection and segmentation.

To a computer, an image is a large 3‑dimensional array of numbers. For example, a colour image of size 248×400248 \times 400248×400 pixels with three colour channels (Red, Green, Blue) contains 248×400×3=297,600248 \times 400 \times 3 = 297,600248×400×3=297,600 integers, each ranging from 000 (black) to 255255255 (white). The classifier must map this huge array of numbers to a single label such as "cat".

1.2 Key Challenges

Even though humans perform image recognition effortlessly, there are many algorithmic challenges:

  • Viewpoint variation: The same object can be oriented in many different ways with respect to the camera.
  • Scale variation: Objects can appear at very different sizes.
  • Deformation: Many objects of interest are not rigid and can be deformed in extreme ways.
  • Occlusion: Parts of the object can be hidden.
  • Illumination conditions: Lighting heavily affects the pixel values.
  • Background clutter: The object may blend into its surroundings.
  • Intra‑class variation: A single category (e.g. chair) may have many different visual appearances.

A good classifier must be invariant to the cross‑product of all these variations while remaining sensitive to inter‑class differences.

1.3 The Data‑Driven Approach and Supervised Learning

We do not attempt to write explicit rules for each category. Instead, we adopt a data‑driven approach: we collect a training dataset of labelled images and then use a learning algorithm to discover the visual appearance of each class.

In the broad framework of supervised learning (as defined in CS229), we have a training set of mmm examples:

{(x(i),y(i))∣i=1,…,m}\{ (x^{(i)}, y^{(i)}) \mid i = 1, \dots, m \} {(x(i),y(i))∣i=1,…,m}

where x(i)∈Xx^{(i)} \in \mathcal{X}x(i)∈X is the input (e.g., an image flattened into a vector) and y(i)∈Yy^{(i)} \in \mathcal{Y}y(i)∈Y is the target label. The goal is to learn a hypothesis h:X↦Yh: \mathcal{X} \mapsto \mathcal{Y}h:X↦Y so that h(x)h(x)h(x) is a good predictor for the corresponding yyy.

  • When yyy is continuous we call the problem regression.
  • When yyy takes on only a small number of discrete values we call it classification.

The image classification pipeline can therefore be formalised as:

  1. Input: A training set of NNN images, each labelled with one of KKK classes.
  2. Learning: Use the training set to learn a classifier (i.e., a hypothesis hhh).
  3. Evaluation: Predict labels for a new set of images (the test set) and compare the predictions with the ground truth.

2. The k‑Nearest Neighbour Classifier

As our first classifier we consider the k‑Nearest Neighbour (kNN). It is a non‑parametric method that simply memorises the training data. It serves as an excellent introduction to data‑driven methods.

2.1 The Nearest Neighbour (NN) Classifier

Training amounts to storing the entire training set. To classify a test image, we compare it to every training image using a distance metric and assign the label of the closest training example.

Example dataset: CIFAR‑10
CIFAR‑10 consists of 60,000 tiny colour images (32×32×332 \times 32 \times 332×32×3), divided into 10 classes (airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck). There are 50,000 training images and 10,000 test images.

Distance metrics
Given two images represented as vectors I1,I2∈RDI_1, I_2 \in \mathbb{R}^DI1​,I2​∈RD (where DDD is the total number of pixels times colour channels), two common choices are:

  • L1 distance (Manhattan):

    d1(I1,I2)=∑p=1D∣I1p−I2p∣d_1(I_1, I_2) = \sum_{p=1}^D | I_1^p - I_2^p | d1​(I1​,I2​)=p=1∑D​∣I1p​−I2p​∣

  • L2 distance (Euclidean):

    d2(I1,I2)=∑p=1D(I1p−I2p)2d_2(I_1, I_2) = \sqrt{ \sum_{p=1}^D ( I_1^p - I_2^p )^2 } d2​(I1​,I2​)=p=1∑D​(I1p​−I2p​)2​

Because the square root is a monotonic function, the ordering of the nearest neighbours is identical whether or not we include the square root, so in practice it may be omitted.

On CIFAR‑10, the simple Nearest Neighbour classifier (k=1) with L1 distance achieves only about 38.6% accuracy – much better than random guessing (10%) but far from human performance (~94%) and state‑of‑the‑art convolutional networks (~95%).

2.2 k‑Nearest Neighbour (kNN)

Instead of using only the single closest example, we retrieve the k closest training images and take a majority vote. Larger values of kkk lead to smoother decision boundaries and are less sensitive to outliers.

Pros and Cons

  • Pros: No training time; very easy to implement.
  • Cons: Must store the whole training set; test‑time prediction is expensive because it requires comparing against all training examples. Moreover, pixel‑based L1/L2 distances in high‑dimensional spaces correlate poorly with semantic similarity, as they are dominated by background and colour distributions rather than object identity.

2.3 Hyperparameter Tuning: Validation Sets and Cross‑Validation

The choice of kkk and the distance metric are hyperparameters. They are not learned from the training data but must be chosen before learning.

Golden rule: never tune hyperparameters on the test set.
The test set should be used only once, at the very end, to estimate the generalisation error of the final model. If you tune hyperparameters using the test set, you will overfit to it and the reported performance will be overly optimistic.

Validation set
We split the original training set into a smaller training set and a validation set (e.g., use 49,000 images for training and 1,000 for validation). We evaluate different hyperparameter choices on the validation set and pick the best configuration. Only at the very end do we evaluate on the test set.

Cross‑validation
When training data is scarce, we can use cross‑validation to obtain a more reliable estimate of the best hyperparameters. In 5‑fold cross‑validation we split the training data into 5 equal folds, train on 4 and validate on the fifth, and repeat this for each fold. The average validation accuracy across folds is used to select the hyperparameters.

In practice a single validation split is computationally cheaper and is often preferred, unless the amount of validation data would be extremely small.

Practical kNN workflow:

  1. Preprocess the data: normalise features to have zero mean and unit variance (for images, zero‑centring is usually sufficient).
  2. If the data is very high‑dimensional, consider dimensionality reduction (e.g., PCA).
  3. Split the training data into train/validation (or use cross‑validation).
  4. Search over many values of kkk and distance types; choose those that give the best validation performance.
  5. If the kNN retrieval is too slow, use an Approximate Nearest Neighbour library (e.g., FLANN).
  6. Evaluate the final model on the test set exactly once and report the accuracy.

3. Linear Classification

We now move to a parametric approach. Once the parameters are learned, the training data can be discarded, and predictions on new images are extremely fast. This paradigm will eventually lead us to neural networks.

3.1 Parameterised Mapping from Pixels to Scores

A linear classifier maps input vectors xi∈RDx_i \in \mathbb{R}^Dxi​∈RD (flattened images) to a vector of class scores s∈RKs \in \mathbb{R}^Ks∈RK using a linear function:

f(xi,W,b)=Wxi+bf(x_i, W, b) = W x_i + b f(xi​,W,b)=Wxi​+b

  • WWW is a K×DK \times DK×D weight matrix. Each row wjTw_j^TwjT​ is a classifier for class jjj.
  • bbb is a K×1K \times 1K×1 bias vector.
  • For CIFAR‑10, D=3072D = 3072D=3072 (32×32×3) and K=10K = 10K=10.

Bias trick
We can simplify the notation by appending a constant 111 to every input vector xix_ixi​ and absorbing the bias into the weight matrix. Then xix_ixi​ is [3073×1][3073 \times 1][3073×1] and WWW is [10×3073][10 \times 3073][10×3073]. The score function becomes a single matrix multiplication:

f(xi,W)=Wxif(x_i, W) = W x_i f(xi​,W)=Wxi​

The extra column of WWW now corresponds to the bias vector bbb.

Interpreting a linear classifier

  • The score for a class is a weighted sum of all pixel values across all colour channels. Depending on the sign of the weights, the classifier can “like” or “dislike” certain colours at certain positions.
  • Each row of WWW can be seen as a template (prototype) for that class. The dot product wjTxiw_j^T x_iwjT​xi​ measures how well the image matches the template.
  • Geometrically, in the high‑dimensional input space each class is separated from the others by a hyperplane. The weight vector wjw_jwj​ is normal to the separating hyperplane for class jjj, and the bias translates the hyperplane away from the origin.

Image data preprocessing
It is good practice to centre the data by subtracting the mean image (computed over the training set). This shifts the pixel values so that they are roughly in the range [−127,127][-127, 127][−127,127] instead of [0,255][0, 255][0,255], and it often helps optimisation.

3.2 Loss Functions

The weights WWW and bbb are parameters we control. Our goal is to choose them so that the predicted class scores are consistent with the ground‑truth labels. We measure our unhappiness with the current set of parameters using a loss function (also called a cost function or objective).

In supervised learning, a common approach is to define a loss that is small when predictions match the labels and large otherwise. Then we search for the parameters that minimise the total loss over the training set.

3.2.2 Softmax Classifier (Cross‑Entropy Loss)

While the SVM loss treats the scores as uncalibrated class confidence values, the Softmax classifier provides a probabilistic interpretation. The scores are transformed into a normalised probability distribution using the softmax function:

Minimising it is equivalent to performing maximum likelihood estimation (MLE) under the model.

Probability interpretation and confidence
The outputs of a Softmax classifier can be interpreted as estimated probabilities p(yi∣xi;W)p(y_i \mid x_i; W)p(yi​∣xi​;W). However, the “peakiness” of these probabilities depends on the regularisation strength λ\lambdaλ: stronger regularisation forces the weights to be smaller, which makes the probability distribution more uniform. Therefore the absolute probability values should be treated with caution; the ordering of class scores is still meaningful.

3.2.3 SVM vs. Softmax

SVM (hinge loss) Softmax (cross‑entropy loss)
Only cares about the margin; once satisfied, loss is zero. Always tries to increase the probability of the correct class, never fully satisfied.
Loss is local: changes to scores of already correctly classified examples (with margin) do not affect the loss. Loss is global: any change in scores changes the probabilities and therefore the loss.
Outputs are scores with no intrinsic meaning beyond ordering. Outputs can be interpreted as (unnormalised) probabilities.

In practice, the performance of SVM and Softmax classifiers is usually very similar, and the choice depends on the specific problem and personal preference.

3.3 Connecting to Linear Regression (CS229 Insight)

The cross‑entropy loss can be seen as a natural extension of the squared error loss used in linear regression. This probabilistic view unifies regression and classification: we choose the loss function that corresponds to the negative log‑likelihood of the assumed noise model (Gaussian → L2 loss, Bernoulli → logistic loss, multinomial → softmax/cross‑entropy loss).

In the Generalized Linear Models (GLM) framework, both linear regression and logistic/softmax regression arise as special cases when the response variable follows an exponential family distribution. The natural parameter η\etaη is modelled as a linear function of the inputs, η=θTx\eta = \theta^T xη=θTx, and the mean of the distribution μ=g−1(η)\mu = g^{-1}(\eta)μ=g−1(η) is the prediction. For Gaussian, ggg is the identity; for Bernoulli, ggg is the logistic function; for multinomial, ggg is the softmax function.

3.4 Optimisation: Preview

Both SVM and Softmax losses, together with their regularisation terms, define a convex (or, in the case of the Softmax, strictly convex) objective function in terms of the weight matrix WWW. The next step is to find the weights that minimise this loss. This is done using iterative optimisation algorithms such as gradient descent:

Repeat until convergence:

θj:=θj−α∂∂θjJ(θ)\theta_j := \theta_j - \alpha \frac{\partial}{\partial \theta_j} J(\theta) θj​:=θj​−α∂θj​∂​J(θ)

where α\alphaα is the learning rate. When applied to the whole dataset at once it is called batch gradient descent; when applied to one example at a time it is stochastic gradient descent (SGD). SGD is often much faster for large datasets and is the workhorse of modern deep learning.

Analytic solution
For linear regression with the squared error loss, there exists a closed‑form solution via the normal equations:

θ=(XTX)−1XTy\theta = (X^T X)^{-1} X^T \mathbf{y} θ=(XTX)−1XTy

However, for the hinge‑loss and for logistic/softmax regression there is no closed‑form solution, and we must rely on gradient‑based optimisation.

3.5 Summary of Linear Classification

  • We defined a linear score function f(xi;W)=Wxif(x_i; W) = W x_if(xi​;W)=Wxi​ that maps image pixels to class scores. The parameters WWW are learned from data.
  • Unlike kNN, this is a parametric approach: after training we only keep WWW, and prediction on a new test image is a single matrix multiplication.
  • We introduced the bias trick to fold the bias vector into WWW, simplifying notation.
  • We defined two widely used loss functions: the Multiclass SVM loss (hinge loss) and the Softmax loss (cross‑entropy loss). Both measures how well the scores match the ground truth labels.
  • Regularisation (L2 penalty) is added to encourage smaller weights and improve generalisation; it can be interpreted as a Gaussian prior over the weights.
  • The probabilistic interpretation of the Softmax loss links it directly to logistic regression and maximum likelihood estimation, providing a natural motivation via the GLM framework.

Now that we have a loss function that measures the quality of any given set of weights, the next fundamental problem is optimisation – how to efficiently find the weights that minimise the loss. This will be the subject of the following lecture.
